합계: 멀티턴 대화 400건 초안 작성. 이전 시범 30건은 사용자 위임 Codex 검토로 로컬 승인본을 구성했습니다. 수정된 초안에는 자동 승계하지 않으며 독립적인 복수 사람 검수는 남았습니다. 제안 정답의 오프라인 재생은 400/400건 통과했습니다. 직접 등록 20건과 validation 다중 후보 선택 5건을 포함합니다. API 실패·응답 유실·재시도는 본 400건에 없고 별도 미검수 진단 10건에 있습니다. 현재 단일 발화 100문항은 별도 평가입니다. 기존 6필드에는 location이 있지만 새 멀티턴 평가에는 두지 않습니다.

AI·DATA 로컬 시범 기준: 조회 후보가 여러 건이면 ID 없는 SELECT_TARGET으로 번호를 먼저 묻습니다. 실제 모델 호출의 action JSON만 학습 행으로 만듭니다. train 25건·validation 5건의 로컬 승인본을 시범 20-step 학습에 사용했으며 독립 재검수는 남았습니다. ai/ 로컬 시범의 action 정렬은 완료됐고, 어댑터 실행 연결·test 고정·공유 계약 확정은 아직 남아 있습니다.

Qwen의 제안 → 프로그램의 처리

Qwen action프로그램Schedule API
ASK부족한 값 질문쓰기 없음
LIST후보 일정 조회GET /api/v1/schedules

SELECT_TARGET AI·DATA 로컬 시범후보 2~10건일 때 ID 없이 번호 선택 요청 → 대상 확정 후 확인쓰기 없음

제안 상태 · TBD-AI: AI·DATA 로컬 시범은 SELECT_TARGET 형식과 번호 선택 흐름을 맞췄습니다. 학습 어댑터는 AI 실행기에 연결되지 않았고 공유 출력 계약은 확정되지 않았습니다. Qwen은 API를 직접 호출하지 않고 대화 관리 프로그램이 값 검증과 호출을 맡습니다.

사람 검토: 안전 위반 후보와 자동 판정이 애매한 사례는 전부 읽고, 나머지는 행동·성공 여부별로 골고루 뽑습니다. 질문의 자연스러움, 확인의 명확성, 결과 안내의 오해 가능성을 적절 / 개선 필요 / 부적절과 근거로 기록합니다. 가능하면 모델 이름을 가리고 같은 기준으로 비교하며, 정성 결과는 주 성공률과 별도 보고합니다.

API 실패·응답 유실·재시도 시나리오는 아직 없습니다. 허용 경로와 사람 검토 기준을 시범 표본에서 정하고 부족한 사례를 보강한 뒤 test를 잠급니다. 평가기 오류를 고치면 버전을 기록하고 BEFORE·AFTER를 모두 다시 채점합니다. 텍스트 시범 구현과 향후 STT·TTS 포함 음성 지연은 구분합니다.
