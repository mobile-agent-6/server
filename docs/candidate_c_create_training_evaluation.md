# 후보 C 일정 등록 데이터 구축 및 MLX 학습 검증 결과

- Issue: #32
- 작성일: 2026-10-29 (Asia/Seoul)
- 범위: 후보 C 출력 형식의 학습 가능성 검증. 출력 계약 채택, 배포 모델 확정, Orange Pi 성능은 이 문서의 범위가 아니다.

## 1. 요약

Qwen3-4B(4비트 MLX)에 후보 C 형식 데이터로 QLoRA 학습을 6회 실행하고, Issue #30의 고정 시험 56건(locked56)으로 평가했다. 평가는 사전 등록 규칙에 따라 위험 오답(`unsafe_accept`)이 처음 나온 사례에서 멈춘다.

- 기본 모델(학습 없음)은 56건 중 1건 정답, 일정 추가 20건 중 0건 정답이었다.
- 마지막 run 006은 52번째 사례까지 진행했다(이전 최장 28건). 일정 추가 20건 중 11건 정답, 수정, 삭제, 조회 32건에서 위험 오답 0건이었다.
- run 006은 lk52(후속 답변 턴의 날짜 정정 누락)에서 멈췄다. 56건 완주와 Test 50 평가는 달성하지 못했다.
- 실패 원인은 회차마다 달랐고(출력 순서, 작업 종류 혼동, 조회 조건 누락, 턴 간 정정), 각각 데이터 보강이나 백엔드 검사로 대응할 수 있는 유형이었다.

후보 C는 멀티턴 형식이다. 모델은 사용자 입력마다 그 시점까지의 대화를 받고, 근거마다 원문 턴 번호를 함께 출력한다.

## 2. 데이터

| 묶음 | 건수 | 내용 |
|---|---:|---|
| pilot, batch 1~3 | 400 | 일정 추가(create). 직접 등록, 날짜와 시간 누락 후속, 같은 턴 정정, 지원 안 하는 요청 혼합 등 |
| batch 4 | 50 | 추가가 아닌 요청: 수정 20, 삭제 15, 조회 15 |
| batch 5 | 37 | 보강: 조회 22(완료 조건, 앞으로 남은, 분류 조건 등), 수정 15 |
| Test 50 | 50 | 학습과 조정에 쓰지 않는 별도 시험. 새 대화 유형으로 구성하고 잠금 |

- 학습 509행, 검증 61행. 검증은 대화 유형(family) 단위로 떼어 학습과 겹치지 않게 했다.
- 모든 묶음은 작성자가 아닌 검수자의 전수 검수를 거쳤고, 검수 판정은 각 묶음의 `review-events-v0.1.jsonl`에 기록했다.
- 생성 단계에서 C 형식 검사, 역할 검사, locked56와 Test 50 대비 문장 유사도와 제목 겹침 검사를 실행했다.

## 4. 평가 방법

- locked56: Issue #30 고정 시험. `ollama_eval_v0_3` 채점기와 공통 안전 검사(common gate)를 MLX 서버에 연결해 사용했다.
- 위험 오답이 나오면 그 run의 평가를 멈추고 재개하거나 수정하지 않는다(사전 등록).
- Test 50: locked56을 위험 오답 없이 마친 경우에만 실행한다. 정답 출력 기준 최대 점수는 48점이다(과거 시각 2건은 안전한 거절이 정답).

## 6. 회차별 실패 원인과 대응

| run | 원인 | 대응 |
|---|---|---|
| 001~003 | 정답 JSON을 알파벳 순서로 직렬화해 `missingInformation`이 `operations`보다 먼저 나옴. 모델이 작업 내용보다 누락 판단을 먼저 쓰게 됨 | 진단 학습(probe A, B)으로 확인 후 schema 순서로 변경 |
| 004 | 학습 데이터가 모두 일정 추가라 "…으로 옮겨 줘"(수정)를 추가로 출력 | batch 4(수정, 삭제, 조회 50건) |
| 005 | 조회에서 "아직 안 끝난" 완료 조건을 빠뜨림 | batch 5(완료 조건 조회 등 37건) |
| 006 | "모레요" 답변 뒤 "모레 말고 글피로 바꿔 줘"의 정정을 무시하고 모레로 등록 | 후속 턴 정정 데이터 보강, 백엔드 정정 검사(후속 과제) |

run 006의 lk52 진단은 같은 모델로 해당 사례만 다시 실행해 기록된 출력 해시와 일치함을 확인했다. run 디렉터리는 수정하지 않았다.

## 7. 해석과 한계

- 학습할수록 진행 사례 수가 늘고, 이전 run을 멈춘 사례가 다음 run에서 안전하게 처리됐다. C 형식은 학습 가능한 출력으로 판단한다.
- 일정 추가 정답 11/20은 아직 낮다. 나머지는 대부분 안전한 거절이나 과도한 질문으로 끝났다.
- 비교 기준은 학습하지 않은 기본 모델이다. 기존 A 형식 데이터로 학습한 모델과는 같은 조건으로 비교하지 않았다.
- Test 50을 실행하지 못해 처음 보는 대화 유형에 대한 일반화는 확인하지 못했다.
- batch 5 일부는 locked56의 문장 형태를 참고해 만들었다(검수자 지적). lk23 등의 통과가 문형 암기일 수 있다.
- 학습량(epoch)은 2로 고정했고 1이나 3과 비교하지 않았다.
- 결과는 Apple Silicon MLX 기준이다. Orange Pi용 변환과 실기기 성능은 확인하지 않았다.

## 8. 후속 과제

1. 데이터: 후속 턴 정정, 수정, 삭제, 조회 기능별 확장, 여러 요청 한 번에
2. 백엔드: C 출력 연결, 변환 규칙 이전, 버그 수정("완료 안 된", "저녁 12시" 등), 정정 검사 등
3. 학습: 1 epoch와 2 epoch 비교, 같은 조건의 A 형식 학습 모델과 비교, 다음 모델로 Test 50 평가
4. 배포: run 006 모델로 Orange Pi 변환 시험
