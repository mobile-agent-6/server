# 물류 일정 Qwen 440건 학습 + v37 멀티턴 보완

상태: DATA 내부 개발 결과 및 백엔드 검토용 전달 자료. 공유 계약 확정이나 실제 API 배포 변경이 아니다.

현재 구성은 **고유 440예시 학습 모델 + v37 후처리**다. 기존 400개에 중간 시점 40개를 추가 학습했고, 마지막 학습은 신규 40 + 기존 20 재학습으로 60스텝이었다. 이후 v37까지는 후처리 개선이며 추가 학습은 하지 않았다.

## 백엔드 보완 요청과 산출물

| 요청 | 제공한 자료 |
|---|---|
| 기존 멀티턴의 시점별 정답 | 기존 184개 전체를 381시점으로 전환. 신규 중간 정답 197개, 전체 고유 입력 356개 |
| 정보 보완·정정·대상 지정 | 시나리오와 각 모델 호출의 evidence·부족 정보 정답 |
| 3·4·5라운드 각각 20개 | 교대 대화 60개, 5개 기능별 12개 대화 |
| 실행 처리 보완 | v37 후처리 및 저장 출력 재평가 |

**신규 중간 정답 197개는 아직 학습하지 않았다.** 원본 184개에는 Assistant/API 로그가 없으므로 누적 userTurns 기준의 정답으로 전환했다. 별도의 교대 대화 60개는 작성한 기대 시나리오이며 실제 API 관측 기록이 아니다.

## 평가

| 개발 자료 | v36 | v37 |
|---|---:|---:|
| 전체 60대화의 고유 모델 입력 132건 | 117/132 | 132/132 |
| 기존 184개 파생 중간 입력 90건 | 90/90 | 90/90 |
| 두 턴 집중 24건 / 16건 | 24/24 / 16/16 | 24/24 / 16/16 |

v37은 기존 오답 15건을 열람하고 보완했다. 13건은 명확한 정정에도 확인 질문을 반환하던 사례, 2건은 정정 전 시간의 출처 턴 오류와 불필요한 삭제 대상 분류였다. 기존 25개 자료군에서 정답 퇴보 0건, 규칙·원문 변형·경계 검사 378개를 통과했다.

**개발 자료에서의 일치율이며 전체 서비스 성능 100%나 독립 Test, 실제 API 성공률을 의미하지 않는다.** 이 버전에서 새 모델 추론·추가 학습은 하지 않았다. 서로 다른 목적의 평가를 합산하지 않는다.

## 파일

- `data/training/`: 실제 학습 400개, 마지막 60개 및 신규 40개 출처
- `data/legacy184-prefix/`: 381시점 후보 정답, 원본·검수본·변경 기록·검증기
- `data/multiturn60/`: 60대화, 179개 호출 정답, 고유 132입력과 현재 학습 사용 여부
- `runtime/rules/`: v37과 실제 의존 모듈 및 선택적 provider 연결 예시
- `runtime/backend/`: CPU 검증에 쓰는 참조 계약 사본. 실제 backend를 덮어쓰지 않음
- `evaluation/selected-v37-summary.json`: 현재 버전의 자료군별 재평가
- `evaluation/remaining15-resolution.json`: 기존 15건의 수정 전후
- `INTEGRATION.txt`, `KNOWN_ISSUES.txt`: 연결 방법과 검증 한계
- `model-info.json`, `model-artifacts.json`: 모델 파일·추론 설정·Release 식별 정보

기존 정답 41개의 정정 배열 순서 정리, 원문 124행 한 건의 수정 제안을 기록했다. 원본 400개는 그대로 보존했다. 전체 381개를 기존 400개에 단순 추가하면 중복되므로 추가 학습 전 출처 기반 교체·중복 제거가 필요하다. 하위 README의 v31은 작성 당시 기록이고 현재 선택은 v37이다.

## CPU 검증

저장소 루트에서 Python 3.11 이상 및 Asia/Seoul 시간대 자료를 사용한다. GPU·MLX·네트워크는 필요 없다.

```bash
python3 datasets/qwen/experiments/logistics440_v37/tools/verify.py
```

파일 무결성, 교대 60개 시나리오, 기존 184개 전환 데이터, 저장 모델 출력 310건을 검증한다. Git 구성에는 가중치와 tokenizer가 없으므로 기본 실행의 해당 검사 항목은 false다.

Release ZIP을 풀고 가중치·tokenizer까지 확인하려면:

```bash
python3 datasets/qwen/experiments/logistics440_v37/tools/verify.py --artifact-bundle /실제/압축해제경로/bundle
```

기본 모델 본체 확인에는 `--base-model /실제/기본모델/model.safetensors`를 추가한다.

## 가중치 전달 및 실제 연결

가중치·tokenizer·전체 검토 자료 ZIP은 [v37 Release](https://github.com/mobile-agent-6/server/releases/tag/qwen-logistics440-v37-20261111)로 별도 전달한다. 다운로드 가능 여부는 Release에서 확인하며, 파일 크기와 SHA-256은 `model-artifacts.json`에 있다. 기본 모델 본체는 제외되어 있고 해시가 같은 기존 전달본을 재사용한다.

학습 LoRA는 API 연결용 어댑터와 별개이며 MLX 형식이다. GGUF/RKLLM 변환 완료본이 아니다. 실제 API/DB, 누적 userTurns 초기화 정책, 선택·승인 흐름, Orange Pi 변환·로딩·속도는 별도 검증이 필요하다. 이 자료 공유로 관련 TBD 계약을 확정하지 않는다.
