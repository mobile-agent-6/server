기존184개 멀티턴의 호출 시점별 정답 전환 후보
작성일: 2026-11-11
현재 모델: 440건 학습 + v31 유지. 학습·추론·배포·커밋·푸시는 수행하지 않음.

완료한 범위
- 기존400개 학습 데이터 중 멀티턴184개를 모두 검토.
- 기존 최종 시점184개 + 새 중간 시점197개 = 381개 호출 시점.
- 동일 입력(context 포함)을 중복 제거하면 전체356개, 새 중간 정답172개.
- 사용자 발화 이력만 기준으로169종류였지만 기준시각 등 입력 문맥까지 포함하면172개.
- 첫 시점의 evidence와 부족 정보, 두 번째·세 번째 시점의 누적 evidence를 분리.
- 신규 중간 정답은 annotations.tsv에 명시적으로 작성. 최종 target을 잘라 생성하지 않음.
- 기존 최종 정답41개의 정정 배열 순서를 superseded → correction_marker → adopted로 정리.
- 124행의 '아 오후4시로'는 정정 표현이 약해 '아니 오후4시로'로 최소 수정한 후보를 작성하고, 이전2시·정정표지·새4시를 기록. source-text-repair-proposal.json에 원문/수정/정답 차이를 보관.
- 원본 source/train400.jsonl과 기존 프로젝트 파일은 수정하지 않음.

파일
- 턴별정답_눈검수.txt: 사람이 읽기 쉬운 전체 대화 시점과 정답.
- new-intermediate197-candidate.jsonl: 새 중간 정답197개(중복 포함).
- prefix-all381-candidate.jsonl: 기존 최종 시점까지 포함한381개(124행 최종은 명시적 수정 후보).
- unique-prefix-candidate.jsonl: 문맥까지 동일한 입력을 중복 제거한356개.
- prefix-all381-index.jsonl, unique-prefix-index.jsonl: 원본 행·시점·기능·정답 출처 매핑.
- final184-reviewed-candidate.jsonl: 검토한 최종 시점184개.
- final-order-normalizations.json: 정정 배열 순서를 바꾼41개 상세 차이.
- transition-review.json: 이전 시점에서 바뀐 evidence와 부족 정보.
- source-text-repair-proposal.json: 유일한 입력 문장 수정 제안1개.
- split-policy.json: 원본 대화와 공유 이력을 분리하지 않는 최소 묶음.
- source/: 수정하지 않은 기존 학습400개와 기준 가이드 사본.

검증
Python3.11이상에서 이 폴더의 verify.py 실행:
  python3 verify.py
GPU·MLX·네트워크 없이 검사 가능. 데이터와 기대 정답 검증이며 모델 정확도가 아님.
원문/역할/턴 번호, 미래 정보 누출, 부족 정보, 정정 순서, 같은 입력의 정답 충돌,
예전 값 유지와 후속 정정, 중복 제거 및 원본 보존을 확인.
AI가 정답을 작성하고 자동 검사 및 의미 규칙으로 검토한 자료. 독립 사람 검수나 실제 API 검증을 주장하지 않음.

학습에 사용할 때
- 아직 학습하지 않은 후보 데이터다. 현재 모델에 이 자료가 반영된 것이 아니다.
- 전체381개를 기존400개에 그대로 더하면 기존 최종 정답이 중복되고 배열 순서가 다른 정답이 충돌할 수 있음.
- 신규 중간 시점만 사용할 경우 먼저 문맥 기준으로 중복 제거하고 기존 학습 파일과 대조.
- 전체 교체 방식이면 기존 멀티턴184행을 이381행으로 대체하며, 기존 단일턴216행은 유지하는 방식으로 준비.
- 기존40개 추가학습·20개 재학습 자료와도 동일 입력/정답 충돌을 확인한 다음 학습 계획을 세움.
- 기존 학습 대화에서 파생된 자료이므로 무작위 행 분할 후 독립 테스트라고 부르지 않음.

대화/API 범위
이 자료는 기존에 묶여 있던 userTurns의 시점별 학습 target 전환이다.
원본에는 Assistant 발화/DB 후보/승인 로그가 없으므로 이를 실제 API 대화처럼 만들지 않았다.
apiDialogueTurn=null, modelPrefixLength는 실제 모델 입력으로 가정한 사용자 발화 수.
질문·선택·승인·조회 결과 이후에는 백엔드가 상태를 비울 수 있어 실제API의 userTurns는 이 누적 이력과 달라질 수 있음.
사용자·Assistant 교대3/4/5라운드60개와 그179개 정답은 기존에 별도 작성된 자료다.
