# 물류 일정 학습 데이터 1,000건

작성일: 2026-11-12. 상태: `DATA 내부 실험 / PROPOSED_UNREVIEWED`.

사용자의 임의 유사 데이터 확장 요청에 따라 기존 물류 v37 학습 예시 440건에 합성 변형 560건을 추가했다. **데이터 파일을 1,000건으로 확장한 것이며 모델을 추가 학습한 결과가 아니다.** 기존 v37 모델의 실제 학습 수량은 여전히 440건이다. 공유 AI 출력·DATA schema의 결정 상태는 변경하지 않는다.

| 기능 | 기존 | 추가 | 합계 |
|---|---:|---:|---:|
| 등록 | 88 | 112 | 200 |
| 조회 | 88 | 112 | 200 |
| 수정 | 88 | 112 | 200 |
| 삭제 | 88 | 112 | 200 |
| 완료·미완료 변경 | 88 | 112 | 200 |
| 합계 | 440 | 560 | 1,000 |

완료 변경은 기존 형식대로 `kind=update`, `changeEvidence.completed`로 표현한다. 건수는 모델 입력·정답 한 쌍을 기준으로 하며, 같은 대화의 중간 시점과 파생 변형이 포함되어 있다. 독립된 1,000개 대화 family를 뜻하지 않는다.

## 파일과 생성 방식

- `train1000.jsonl`: 기존 440건을 앞부분에 그대로 보존한 전체 학습 후보. 각 행은 기존과 같은 system/user/assistant `messages`다.
- `synthetic560.jsonl`: 전체 파일의 마지막 560건과 같은 추가분. 두 파일을 합치면 중복되므로 전체 학습에는 `train1000.jsonl` 하나를 사용한다.
- `train1000-index.jsonl`: 행별 원본 파일·행·입력 해시, 기능, 제목 치환, 미검수 상태와 계보. 추가분은 원본 문형의 파생 자료이며 독립 family로 분류하지 않는다.
- `build.py`: 고정 seed `20261112`로 생성·검증하는 표준 라이브러리 기반 도구. 저장소의 현재 backend evidence 검사기를 읽기 전용으로 사용한다.
- `validation.json`, `manifest.json`: 자동 검사 결과와 입력 의존 파일·산출물의 SHA-256.

원본은 [v37의 기존 400건과 추가 40건](../logistics440_v37/data/training/)이다. 제목이 명시된 기존 예시를 기능별로 골라 물류 구역·작업·점검 표현을 조합한 새 제목으로 바꿨다. 사용자 원문과 정답의 제목을 함께 변경하고 원래 제목의 분류 cue와 종성 유무를 보존한다. 날짜·시각·정정 구조·누락 정보·다중 턴 구조·시스템 프롬프트는 원본을 따른다. 학습·검증 원본과 v37 전달본은 수정하지 않는다.

현재 요청은 기존 총량을 1,000건으로 늘리는 합성 실험이다. 기존 공통 제작 가이드 제안의 기능별 400개, 신규 family 보강 1,000개, 독립 검수·잠금 Test 요건을 완료했다는 뜻이 아니다. 추가분의 `reviewState`는 `PROPOSED_UNREVIEWED`로 유지한다.

## 재현과 확인

저장소 루트에서 Python 3.11 이상으로 실행한다. 별도 의존성 설치, 네트워크, 모델 가중치, API·DB 접근은 필요 없다.

```bash
python -X utf8 datasets/qwen/experiments/logistics1000_v0.1/build.py build
python -X utf8 datasets/qwen/experiments/logistics1000_v0.1/build.py verify
```

`build`는 이 폴더의 생성 JSONL·검증 결과·manifest를 덮어쓴다. `verify`는 파일을 쓰지 않고 원본과 현재 검사기로 재생성한 내용의 바이트 일치를 확인한다. 의존 파일이 달라지면 manifest 비교가 실패하므로 원인을 확인한 후 재생성한다.

이 폴더는 `.gitattributes`로 LF 줄바꿈을 유지한다. 외부 의존 파일의 해시는 UTF-8·LF로 정규화해 계산하므로 Windows의 CRLF 체크아웃에서도 같은 manifest를 재현한다. 산출물 해시는 실제 파일 바이트를 기준으로 한다.

검사 기준은 총 1,000행·기능별 200행, 원본 440행 보존, 고유 입력, 추가분의 공백·NFKC 정규화 대화 중복 없음, v37의 validation과 개발 평가 입력에 대한 추가분의 정규화 대화 완전 중복 없음, 원문 span·역할·겹침 검사 통과, 원본 대비 안전 질문 판정 유지다. 없는 원문 span과 잘못된 operation 역할을 거부하는 검사 2개도 수행한다. 자동 검사는 의미상 정답이나 학습 성능을 보장하지 않는다.

## 한계와 후속 검증

추가 560건은 제목을 바꾼 합성 변형으로 문형·날짜·시각 다양성이 제한적이다. 독립 사람 검수, 모델 학습, 토큰 길이·학습 마스크 검사, 성능 평가, 실제 API 재생은 수행하지 않았다. 전체 파일은 학습 후보이며 validation/Test를 새로 만들지 않았다. 이후 분할할 때는 원본과 파생 예시를 같은 계보로 묶어 분리해야 한다. 기존 검증·평가 자료를 독립 Test로 새로 주장하지 않는다.
